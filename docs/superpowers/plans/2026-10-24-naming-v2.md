# 命名引擎 V2 执行清单

用户已确认上一轮评审方案并要求开始；由当前智能体在本会话顺序执行，不调用子智能体。

目标：完整食材词、可识别梗句式与成对口号，保留价格、热量、组合键和已有投票。
设计来源：2026-10-24 命名引擎评审，以及 HANDOFF.md 第 15 节。

## 全局约束

- 不新增网络请求、构建依赖或在线模型；词库内嵌到既有 logic.js。
- 热梗保留来源与核验日期；十月规矩 / 生活理论句式与常青老己分组。
- 名字必须保留食物指向，品类、规格、食材与所选单品一致。
- 谐音为可选；有替换记录就必须出现在最终名字里。
- 保存词库版本和名称快照；无版本的已存作品通过原算法还原一次并冻结。
- 不改变商品 code 组合键、票数、营养缺失语义或价格的整数分口径。

## 重点验收

- 现有 2500 组完整枚举，顺序无关、食材关联、无汉堡时不命名成堡。
- 其他门店的未知商品 code 从详情名识别，不取首字或借用错误的旧关键词。
- 品类不明时回退完整商品词，不凭空加入食材、大小或包装。
- 老记录迁移前后名称、口号、组合键、票数及已投状态不变；新作品快照跨重载不变。
- Chrome 检查主名、海报、复制、榜单、存储不可用及五档宽度；记录本地耗时与脚本体积。
